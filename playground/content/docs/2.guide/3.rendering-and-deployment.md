## Why `routeRules` Are Opt-In

`@nuxtify/cms` does not force `routeRules` on your content routes by default. While Markdown content typically changes only on deployment, your host application controls the surrounding layout, authentication state, middleware, and hosting target:

- **Dynamic app shells:** If your layout, navbar, or middleware reads session cookies or user state, prerendering `/docs/**` or `/articles/**` bakes a single static snapshot at build time.
- **Large content sites:** Sites with hundreds or thousands of entries may prefer on-demand `isr` or `swr` caching instead of prerendering every route on every CI build.
- **Custom prefixes & redirects:** Content prefixes are customizable via `nuxtifyCms.content.<collection>.routePrefix`, and hosts handle trailing slashes and static redirects differently.

## Full Static Sites (`nuxt generate`)

If your entire site is static, run `nuxt generate` (or set `ssr: true` with static preset). Nuxt crawls and prerenders all linked CMS routes automatically without extra `routeRules`.

## Hybrid Apps with SSG Content

When your app has dynamic routes alongside static CMS content, enable `prerender: true` for your content prefixes in `nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  routeRules: {
    '/articles/**': { prerender: true },
    '/docs/**': { prerender: true },
    '/notes/**': { prerender: true },
    '/topics/**': { prerender: true },
    '/contributors/**': { prerender: true },
    '/tags/**': { prerender: true },
  },
})
```

### Custom `routePrefix` Paths

If you customize a collection's `routePrefix` (for example, setting `nuxtifyCms.content.articles.routePrefix` to `'posts'`), update the matching `routeRules` key (e.g. `'/posts/**'`) so Nitro applies prerendering to the active path.

## Serverless & Edge Caching

On platforms that support route-level caching (such as Vercel, Netlify, or Nitro cache storage), you can use `isr` or `swr` instead of build-time prerendering for large content collections:

```ts
export default defineNuxtConfig({
  routeRules: {
    '/articles/**': { isr: 3600 },
    '/docs/**': { swr: true },
  },
})
```

### SQLite on Serverless Hosts

`@nuxt/content` v3 indexes content into SQLite (`better-sqlite3` by default). On serverless or edge runtimes where native SQLite bindings are unavailable at request time, either prerender those routes with `prerender: true` or configure a platform-supported database adapter in `@nuxt/content`.

> **Official Nuxt Docs:** Read the [Nuxt Prerendering Guide](https://nuxt.com/docs/4.x/getting-started/prerendering) for static generation and `routeRules` details, and the [Nuxt Deployment Guide](https://nuxt.com/docs/4.x/getting-started/deployment) for hosting presets and hybrid rendering options.
